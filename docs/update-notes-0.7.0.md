# Steambirds Alliance Revive 0.7.0 (in progress)

**Status: not released.** This file is fed with every change until 0.7.0 is out; add a line here (English and Portuguese) in the same change
that touches the game, the server, the launcher or the editors. / **Em andamento:** este arquivo recebe cada alteração até o lançamento da 0.7.0.

Base: `1b6148c` (the last commit of 0.6.0). / Base: `1b6148c` (último commit da 0.6.0).

## English

### Launcher and editor

- **Choose the Nexus and tutorial maps:** the Server tab, *Maps and dungeons* page, now has a working choice of map file for the Nexus (Rebel City) and for the tutorial (Training Grounds). It is saved in `dungeons.json` (`nexusMap`, `tutorialMap`; the originals are `nexus` and `tutorial_walker`) and the server reads it again by itself: the new map applies to the next player who joins the Nexus or starts the tutorial. A name without a file falls back to the original map (logged). To make a version, open `nexus` or `tutorial_walker` in the Map editor, change it (buildings, spawn, floor, the tutorial `script`...) and use *Save as* with a new name.
- **Server console commands:** the Console page of the Server tab has a command bar. *Run for* picks the player (the game of this PC, all players online, or one player of the list, read from the server), the box takes a chat command (Enter sends it, the arrow keys bring back the last ones) and *Command list...* opens the list of the server's commands (about 70, with a filter and a description each). The launcher writes the line to the standard input of the server and `Server\Admin\ConsoleCommands.cs` runs the command as that player (`Game.RunCommand`, on the thread of the server the player is on), ignoring `chatCommands` of `network.json`. The answer goes to the player's chat and a `[CONSOLE]` line to the console. The same lines work in a terminal: `NAME<TAB>/command`, `*<TAB>/command` or just `/command` (the game of this PC). `/players` lists who is online. Replaces the greyed-out command box.
- **Map preview:** the *Maps and dungeons* page has a *Map preview* card next to the table with a picture of the map of the selected row (or of the Nexus / tutorial choice), drawn by the map editor's own canvas. Without the game pictures the pieces of the Nexus floor are flat squares (the editor does the same now).
- **First-run window runs SteambirdsGameFiles.exe:** after the game is downloaded with Steam (the window of the first run and the Client tab), the launcher runs `SteambirdsGameFiles.exe --game <folder> --no-pause` in a window that shows its output (with Cancel) and, when it ends well, reloads the game data. If the tool is not next to the launcher the message says so.
- **Open in the editor:** each map of that page (Nexus, tutorial and the dungeon of the selected row) has a button that loads the map file in the Map editor tab and goes to it (it asks first about changes the editor has not saved). It replaces the greyed-out "View the selected map".

- **Open world: enemies tab:** *Server > World map* has a new *Enemies* tab. (1) *How enemies spawn* edits the numbers of `world.json` > `enemies` without losing the comments of the file: most enemies alive at once, how close a player must be for a spawn site to create its enemies, when they go away, when a sleeping enemy wakes up, how far a player sees them, the distance between spawn sites, the most enemies in a group, the respawn time multiplier and the health multiplier. (2) *Enemies of each biome* shows, for each of the 12 biomes, the groups its spawn sites pick from (a leader and followers, or a solo enemy): *Add enemy...* picks units of the game (filter, several at once) into a group or a new one, *Remove* takes them out, plus remove and rename group and *Back to the game's list*. A biome you never changed keeps the game's own lists. What you change goes to `world-enemies.json` (new, written by the launcher, read by the server by itself); the game's lists are written by the server to `world-enemy-defaults.json`. Groups already on the map stay until they die.
- **Open world: spawn a boss or a dungeon from the map:** right click the world map for *Spawn boss here* (a submenu with the bosses of the biome under the mouse, each with its number of parts; the chosen boss appears awake at that point together with its parts and minions, for example Gargantua with its fists and laser or Clockboss with its hands and numbers) and *Spawn dungeon carrier here* with a submenu of the dungeons of `dungeons.json`; the new *Spawn dungeon* button next to the map does the same at a random place. The boss of each biome is chosen in the Enemies tab (default: the biggest `BOS` unit of the game's folder of the biome that is not a part, such as Gargantua, Clockboss or Beequeen). The launcher writes a request file in `world-requests\` and the server (`WorldServer.Requests.cs`) answers in `world-request-result.json`, shown next to the button. It needs a player in the open world. The boss and its parts are the game's units with the default AI (no original boss AI yet: the parts do not follow the boss).

### Enemy AI: summons, shields, effects, phases and a graph view

- **Summons, shield and look inside the AI:** a state of an AI file can now summon units (`summon`, `summonCount`, `summonEvery`, `summonMax`:
  at the start of the state and again every few seconds, never more than N alive), put up a **shield** (`shield`, `shieldSeconds`, `shieldEffect`: no
  damage for a while or for the whole state), change the **look** of the unit (`effect`) and turn **homing bullets** on or off (`homing`). New condition
  `summonsAtMost` (the units it summoned that are alive number at most N), so a state can wait for its summons to die. New move mode `builtin`: the
  server's own flight (chase, circle, charge, turret, route...) runs the unit while the states change everything else.
- **Boss phases are AIs now:** a phase is a state that a `healthBelow` transition leads to (phases crossed by one big hit all happen, in order). The old
  `phases` of the unit types and `barks.phase` are gone from the server and from the map editor (the *Phases* tab and the *When the phase changes* field
  were removed). The 24 bosses of the shipped maps and `enemies.json` were converted into `ai\brains\<map>_<type>.json` with the same summons, messages,
  speech, shield, guns and fire rates (SN-Z's shield, the Frozen Horror's five summons, Meowza's nine phases, the tutorial boss...). A community map that
  uses a boss AI has to ship the brain file with it (the launcher's *Export...* packs it).
- **Graph tab:** the Enemy AI editor has a second view, **Graph**, next to *States and transitions* (the list is still the default). A box per state, an
  arrow per transition with its conditions; clicking a state selects it in the list and says what it takes to go from it to every other state (the direct
  transition, or the chain of states in between) and what it takes to arrive at it from each of the others. States can be dragged (the place is saved in
  the file), *Arrange automatically* and *Fit view*. A new tab *Summons and shield* holds the fields above; the simulator draws the shield, counts the summons
  (*Destroy summons* removes them) and shows the effect. In the Graph tab the state the simulator is running is filled in **violet** and marked
  "running" (the selected state keeps the theme's selection color, so the two are never confused).
- **More room to edit:** the name, author, description and first state of an AI or behavior moved to their own **Info** tab, so the states and values use the
  whole height. In *Weapons (mounts)* every gun is now an expandable section (click the name or the arrow; several can be open) instead of one list with a
  details box at the bottom.
- **Help and texts:** new help topics (*Summons, shield and look*, *Phases inside an AI*, *The graph view*) and the Portuguese translation of everything new.
- **Every unit runs an AI; AI files sorted in folders:** the plain `"behavior"` of a unit type is gone from `enemies.json`, from the 17 dungeon maps, from the map-maker catalog and from the open-world and tutorial default types: each type names an AI (`"ai"`). Eleven **generic AIs** (`generic_chase`, `_circle`, `_charge`, `_turret`, `_patrol`, `_escort`, `_idle`, `_fixed`, `_kamikaze`, `_mine`, `_route`) are the old built-in flights as AI files, one per behavior, so no unit lost its movement (walls and crates stay still, cannons fire straight, bombs and mines explode on contact). A type with no `ai` (an old or community map) gets the generic AI of its old `behavior` (chase when it has none). The AI files moved into `airains\generic`, `airains\world` and `airains\dungeons\<dungeon>` (the tutorial is a dungeon); the server and the launcher read the folders inside, and an id must be unique across them. A new `units` list in an AI file says which game units it was made for (an AI in `generic` works for any unit), and an AI may carry its own **embedded behaviors** (`"behaviors"`), usable only by its states. The launcher's Enemy AI tab shows the AIs by folder, has *Edit > Move to folder...* and a *Made for (units)* field; a new unit type of the map editor starts with `generic_chase`. The boss AIs now name their own flight (`builtin`) instead of reading the unit type's `behavior`.
- **Pick the AI of each enemy:** in *Server > World map > Enemies* the list of each biome has an **AI** column and a box *AI of the selected enemy* (saved per biome in `world-enemies.json` > `ai`; default `generic_chase`); in the map editor *Units > Enemy AI* the list of AIs does the same. Both list the AIs made for the enemy first (the `units` of the AI file) and then the generic ones. The button is now **Load unit in the AI editor** (also in the world list): it opens the Enemy AI tab with that unit and its AI loaded.
- **Enemy AI editor: units by origin, the AI of the unit, new behaviors:** the *Unit* box is now a picker with folders: **Dungeons** (each dungeon; the tutorial is one), **World** (each biome, with the AI the host picked) and **Generic** (the types of `enemies.json`), and **Without origin** for game units nothing uses. A unit that lives in several places is listed in each, running the AI that place gives it; units with no AI file are written in another color, and there is a filter. Next to it, an **AI** box lists the AIs that fit the unit (made for it first, then generic) and loads the one you pick on the unit; **Load another AI...** loads any AI of the folders (also those made for other units) or a file from anywhere on the computer (it enters the list as unsaved). In an AI, a state's *Behavior* box lists the behaviors inside the AI and the files of `behaviors\`, and **New behavior...** opens a window of its own for the new behavior: it can stay inside that AI (embedded) or be saved in the behaviors folder; **Edit behavior...** reopens an embedded one (and can move it to the folder).
- **Embedded behaviors keep the name of their AI; the state tab is called "Behavior values":** a behavior made inside an AI is named `<ai id>_<name>` (renaming, copying or importing the AI renames them with it), so it can never have the id of a behavior file (the library reports an error if one does); saving it in the behaviors folder drops the prefix. The tab that used to be *Own values* edits the behavior of the state, so it is now *Behavior values*. An `"ai"` may also be written as a path inside `ai\brains` (`generic/generic_chase`): the file name is the id. A missing AI is reported once in the server log, not once for each unit type that names it (the map-maker catalog has 822).
- **The simulator shows why the AI changes state and what the guns reach:** *Show ways out of the state* (on by default) draws the conditions of the current state's transitions on the map: a circle for a distance (solid = closer than, dashed = farther than), a mark on the health bar for a health value, a clock for a time (with the random time already rolled), a cone for "facing the player", icons for a recent hit, a chance, "has a player" and the number of summons; each transition has its own color, a condition that is true now is thicker and marked, at most 6 are drawn on the map and a list at the bottom has all of them. *Show weapon range* draws, for each gun the state lets fire, how far it shoots and the area where the player has to be for it to shoot (its arc), in the color of the gun; the gun list gets the numbers.
- **Right click on an AI in the list of the Enemy AI tab:** *Duplicate* and *Delete* (the file goes to `server\_backup`, like the Edit menu).


### Fixes

- **Iron Lair mines:** SN-Z's mines went off the moment they were dropped (the boss circles where the players are, so they landed inside the
  trigger area) and again when shot down: two giant rings per mine. Now a mine does nothing until it is *armed*, which happens once no player is
  inside its red ring; from then on it goes off by itself, releasing the ring of shots (`onContact`), only when a player flies into it. A mine
  that is shot down from outside just disappears. SN-Z's shots are not homing anymore. New unit behavior `mine` and map field `onContact`.
- **Safe trade:** a trade request was declined by itself about 1.3 s after it was sent, and the other player then got "no trade to answer". The game client declines on its own when the requester's plane leaves the small trigger area spawned at the request. The server now ignores a decline that arrives in the first 4 s, keeps the request open and tells the target to type `/trade`.

### IA dos inimigos: invocações, escudos, efeitos, fases e vista de grafo

- **Invocações, escudo e aparência dentro da IA:** um estado de um arquivo de IA agora pode invocar unidades (`summon`, `summonCount`, `summonEvery`,
  `summonMax`: quando o estado começa e de novo a cada alguns segundos, nunca mais de N vivas), levantar um **escudo** (`shield`, `shieldSeconds`,
  `shieldEffect`: sem dano por um tempo ou durante o estado todo), mudar a **aparência** da unidade (`effect`) e ligar ou desligar as **balas
  teleguiadas** (`homing`). Condição nova `summonsAtMost` (as unidades que ela invocou e que estão vivas são no máximo N), para um estado esperar as
  invocadas morrerem. Modo de movimento novo `builtin`: o voo próprio do servidor (chase, circle, charge, turret, route...) voa a unidade enquanto os
  estados mudam todo o resto.
- **Fases de chefe agora são IAs:** uma fase é um estado para o qual uma transição `healthBelow` leva (fases cruzadas por um golpe só acontecem todas,
  em ordem). As antigas `phases` dos tipos de unidade e o `barks.phase` saíram do servidor e do editor de mapas (a aba *Phases* e o campo *When the phase
  changes* foram removidos). Os 24 chefes dos mapas que acompanham o jogo e do `enemies.json` foram convertidos em `ai\brains\<mapa>_<tipo>.json` com as
  mesmas invocações, mensagens, falas, escudo, armas e cadências (o escudo do SN-Z, as cinco invocações do Frozen Horror, as nove fases do Meowza, o chefe
  do tutorial...). Um mapa da comunidade que usa a IA de um chefe precisa levar o arquivo da IA junto (o *Export...* do launcher empacota).
- **Aba Graph:** o editor de IA tem uma segunda vista, **Graph**, ao lado de *States and transitions* (a lista continua sendo a padrão). Uma caixa por
  estado, uma seta por transição com as condições; clicar em um estado o seleciona na lista e diz o que é preciso para ir dele a cada um dos outros (a
  transição direta ou a cadeia de estados no meio) e o que é preciso para chegar nele a partir de cada um dos outros. Dá para arrastar os estados (o
  lugar fica salvo no arquivo), *Arrange automatically* e *Fit view*. Uma aba nova *Summons and shield* tem os campos acima; o simulador desenha o
  escudo, conta as invocadas (*Destroy summons* as remove) e mostra o efeito. Na aba Graph o estado que o simulador está executando fica preenchido de **violeta** e marcado como
  "running" (o estado selecionado mantém a cor de seleção do tema, então os dois nunca se confundem).
- **Mais espaço para editar:** nome, autor, descrição e primeiro estado de uma IA ou comportamento foram para uma aba **Info** própria, e os estados e
  valores usam a altura toda. Em *Weapons (mounts)* cada arma agora é uma seção expansível (clique no nome ou na seta; várias podem ficar abertas) em vez
  de uma lista com uma caixa de detalhes embaixo.
- **Ajuda e textos:** tópicos de ajuda novos (*Summons, shield and look*, *Phases inside an AI*, *The graph view*) e a tradução para português de tudo
  que é novo.
- **Toda unidade roda uma IA; arquivos de IA separados em pastas:** o `"behavior"` simples saiu do `enemies.json`, das 17 dungeons, do catálogo do map maker e dos tipos padrão do mundo aberto e do tutorial: cada tipo indica uma IA (`"ai"`). Onze **IAs genéricas** (`generic_chase`, `_circle`, `_charge`, `_turret`, `_patrol`, `_escort`, `_idle`, `_fixed`, `_kamikaze`, `_mine`, `_route`) são os antigos voos embutidos como arquivos de IA, um por behavior, então nenhuma unidade perdeu o movimento (paredes e caixas ficam paradas, canhões atiram reto, bombas e minas explodem ao encostar). Um tipo sem `ai` (mapa antigo ou da comunidade) recebe a IA genérica do `behavior` antigo (chase se não tinha). Os arquivos de IA foram para `airains\generic`, `airains\world` e `airains\dungeons\<dungeon>` (o tutorial é uma dungeon); servidor e launcher leem as pastas de dentro, e o id precisa ser único entre elas. Uma lista nova `units` no arquivo diz para quais unidades do jogo a IA foi feita (uma IA em `generic` serve para qualquer unidade), e uma IA pode ter **behaviors embutidos** (`"behaviors"`), que só os estados dela usam. A aba Enemy AI do launcher mostra as IAs por pasta, tem *Edit > Move to folder...* e o campo *Made for (units)*; um tipo novo do editor de mapas começa com `generic_chase`. As IAs de chefe agora indicam o próprio voo (`builtin`) em vez de ler o `behavior` do tipo.
- **Escolher a IA de cada inimigo:** em *Server > World map > Enemies* a lista de cada bioma tem uma coluna **AI** e a caixa *AI of the selected enemy* (gravada por bioma em `world-enemies.json` > `ai`; padrão `generic_chase`); no editor de mapas, *Units > Enemy AI* faz o mesmo na lista de IAs. As duas mostram primeiro as IAs feitas para o inimigo (o `units` do arquivo da IA) e depois as genéricas. O botão agora se chama **Load unit in the AI editor** (também na lista do mundo): abre a aba Enemy AI com aquela unidade e a IA dela carregadas.
- **Editor de IA dos inimigos: unidades por origem, a IA da unidade, behaviors novas:** a caixa *Unit* agora é um seletor com pastas: **Dungeons** (cada dungeon; o tutorial é uma), **World** (cada bioma, com a IA que o host escolheu) e **Generic** (os tipos do `enemies.json`), e **Without origin** para as unidades do jogo que nada usa. Uma unidade que vive em vários lugares aparece em cada um, com a IA que aquele lugar dá a ela; unidades sem arquivo de IA aparecem em outra cor, e há um filtro. Ao lado, a caixa **AI** lista as IAs que servem para a unidade (primeiro as feitas para ela, depois as genéricas) e carrega na unidade a que você escolher; **Load another AI...** carrega qualquer IA das pastas (também as feitas para outras unidades) ou um arquivo de qualquer lugar do computador (entra na lista como não salvo). Numa IA, a caixa *Behavior* do estado lista as behaviors de dentro da IA e os arquivos de `behaviors\`, e **New behavior...** abre uma janela só da behavior nova: ela pode ficar dentro daquela IA (embutida) ou ser salva na pasta behaviors; **Edit behavior...** reabre uma embutida (e pode movê-la para a pasta).
- **Behaviors embutidas levam o nome da IA; a aba do estado se chama "Behavior values":** uma behavior feita dentro de uma IA se chama `<id da IA>_<nome>` (renomear, copiar ou importar a IA as renomeia junto), então nunca tem o id de um arquivo de behavior (a biblioteca acusa erro se tiver); ao salvar na pasta behaviors o prefixo some. A aba que era *Own values* edita a behavior do estado, por isso agora é *Behavior values*. O `"ai"` também pode ser escrito como caminho dentro de `ai\brains` (`generic/generic_chase`): o nome do arquivo é o id. Uma IA que não existe é avisada uma vez no log do servidor, e não uma vez por tipo de unidade que a cita (o catálogo do map maker tem 822).
- **O simulador mostra por que a IA muda de estado e o que as armas alcançam:** *Show ways out of the state* (ligado por padrão) desenha no mapa as condições das transições do estado atual: um círculo para uma distância (cheio = mais perto que, tracejado = mais longe que), uma marca na barra de vida para um valor de vida, um relógio para um tempo (já com o tempo sorteado), um cone para "virada para o jogador", ícones para dano recente, chance, "tem jogador" e número de invocadas; cada transição tem a própria cor, uma condição verdadeira agora fica mais grossa e marcada, no máximo 6 são desenhadas no mapa e uma lista embaixo tem todas. *Show weapon range* desenha, para cada arma que o estado deixa disparar, até onde ela atira e a área onde o jogador precisa estar para ela atirar (o arco dela), na cor da arma; a lista de armas ganha os números.
- **Botão direito numa IA da lista da aba Enemy AI:** *Duplicate* (duplicar) e *Delete* (apagar; o arquivo vai para `server\_backup`, como no menu Edit).


### Correções

- **Minas da Iron Lair:** as minas do SN-Z explodiam assim que eram soltas (o chefe gira onde os jogadores estão, então caíam dentro da área de
  disparo) e de novo ao serem abatidas: dois anéis gigantes por mina. Agora a mina não faz nada até estar *armada*, o que acontece quando nenhum
  jogador está dentro do anel vermelho; daí em diante ela só explode sozinha, soltando o anel de tiros (`onContact`), quando um jogador voa para
  dentro dele. Mina abatida de fora só some. Os tiros do SN-Z não são mais teleguiados. Comportamento novo `mine` e campo de mapa `onContact`.
- **Troca segura:** o pedido de troca era recusado sozinho cerca de 1,3 s depois de enviado, e o outro jogador recebia "no trade to answer". O cliente do jogo recusa por conta própria quando o avião de quem pediu sai da pequena área (gatilho) criada no pedido.
